# Development and CI dependency set. The container installs
# requirements-prod.txt instead; see the comment at the top of that file.
#
# ---------------------------------------------------------------------------
# Upper bounds added to the starter's pins, and the evidence for each
# ---------------------------------------------------------------------------
# The starter left transformers, torch and torchvision unbounded. Resolved
# fresh on Python 3.12 they now pick up releases published after this course
# was written, and one of them breaks Task 2 outright. Both arms were run:
#
#   transformers 5.22.2  mlflow.transformers.log_model FAILS. MLflow 2.16.2's
#                        transformers flavour imports FlaxPreTrainedModel,
#                        removed in transformers 5. The import failure makes
#                        MLflow's framework detection fall through to
#                        TensorFlow, and the visible error is
#                        "ModuleNotFoundError: No module named 'tensorflow'".
#   transformers 4.57.6  log_model succeeds, the model registers, and the
#                        production alias resolves.
#
# sentence-transformers is bounded as a consequence, not a preference:
# deepchecks[nlp] requires sentence-transformers>=3.0.0, and version 6 requires
# transformers>=5.0.0. Left unbounded it drags the resolution back over the
# line and reintroduces the failure above. With <6 it resolves to 5.7.0 and
# `pip check` reports no broken requirements.
#
# torch is bounded below 3 for the ordinary reason — a major version of the
# tensor library underneath the model is not a transparent upgrade.
